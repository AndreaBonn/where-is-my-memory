## P2 hardening notes (none meets the exploit bar)

1. Cache tools resolved via PATH and run with inherited cwd (fs_controls.py:53, executor_disk_fs.py:114-125). npm/uv read project config from cwd; compose already pins cwd="/". Fix: pass `cwd=` neutral dir to `SubprocessRunner`. Accident scenario needs the app started inside a project with a hostile `.npmrc`; autostart cwd is HOME.
2. Compose set re-check and `down` are not atomic (executor_compose.py:30-36 then compose.py:107): a container started in that few-ms window would be taken down (and its volumes with `-v`). Realistic only on a race by the user's own tool. Fix: none cheap; accept or pass container ids explicitly.
3. `snooze-group` accepts any non-empty string from any same-user process (group_actions.py:21, user_state.py:23); entries persist in state.json until expiry, unbounded count. Same-uid only; cap or validate against the snapshot's group ids.
4. `redact_cmdline`/`SECRET_ARGUMENT` miss short forms (`-p secret`, `-psecret`, `curl -u user:pass`) in the Inspector output (redaction.py:6). Same-uid reader can read /proc/<pid>/cmdline anyway, so no boundary crossed (Q-14 is met for long flags and KEY=value).
5. `SubprocessRunner` captures stdout/stderr unbounded in memory (fs_controls.py:55-62), tail kept afterwards. Local, trusted tools.
6. No cap on `devdirs_roots` count/depth at runtime beyond config ranges; DoS only on own CPU. (Config ranges exist: devdirs_max_depth 1-12.)
